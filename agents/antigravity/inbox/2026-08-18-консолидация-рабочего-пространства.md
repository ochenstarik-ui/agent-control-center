## Что нужно сделать

Собрать в `C:\Users\Ochenstarik\Agent_projects` клоны всех проектов и
убедиться, что в каждом есть папка `agents/`. Ничего разбирать, переносить и
удалять не нужно — только выгрузка из git и проверка структуры.

### 1. Каталог

Создать `C:\Users\Ochenstarik\Agent_projects`, если его нет. Все проекты
живут здесь и только здесь.

### 2. Выгрузить репозитории

Владелец — `ochenstarik-ui`. Проверить, что `gh auth status` показывает
именно его, и склонировать 17 репозиториев:

```bash
cd "C:/Users/Ochenstarik/Agent_projects"
for r in business-platform kagent hermes-config-backup server-monitor-manager \
         randomayzer trade-signal-platform trading-knowledge-base \

done
```

Часть репозиториев приватные — без авторизованного `gh` они не склонируются.
Если какой-то не выгрузился, это в отчёт, а не «пропустил и пошёл дальше».

### 3. Структура agents/

Структура уже лежит в самих репозиториях, отдельно её создавать не надо.
На 2026-08-18 она находится в ветке `chore/agents-workspace` и ждёт приёмки в
открытом PR. Поэтому в каждом клоне:

```bash
git fetch origin
git checkout chore/agents-workspace 2>/dev/null || git checkout main
```

Если к моменту выполнения PR уже смержены — структура будет в `main`, и
переключаться никуда не нужно.

Проверить, что в каждом проекте есть:

```
agents/
  README.md  TASK-TEMPLATE.md  REPORT-TEMPLATE.md
  claude/ codex/ antigravity/ hermes/ grok/ opencode/
      inbox/  done/  notes/
  _accepted/
```

Если в каком-то репозитории `agents/` не оказалось ни в `main`, ни в
`chore/agents-workspace` — не выдумывать структуру самому: записать в отчёт,
какой это репозиторий.

### 4. Как здесь работать дальше

Коротко, полные правила — в `agents/README.md` внутри любого проекта:
задание — в `agents/antigravity/inbox/`, черновики — в `notes/`, результат —
в `done/`. Задание, пришедшее в чате, сначала записывается в `inbox/`, и
только потом начинается работа. Своих папок за пределами
`agents/antigravity/` не заводить — из-за этого всё и разъехалось.

## Границы

- Ничего не удалять и не переносить с диска. Эта задача — только выгрузка.
- В `main` не пушить, PR не мержить.
- Существующие папки с проектами вне `Agent_projects` не трогать: что с ними
  делать, решается отдельной задачей.

## Что здесь ломается

- **Длинные пути Windows.** Часть репозиториев имеет глубокую вложенность и
  падает с `Filename too long`. Лечится `git config --global core.longpaths true`
  до клонирования.
- **Ветка по умолчанию.** У `agent-control-center-server` это `master`, а не
  `main`. Не считать `main` данностью.
- **Занятые файлы.** Если клон не создаётся из-за занятого файла — значит, в
  этой папке работает другой процесс. Не ломать, записать в отчёт.

## Как проверить результат

Считается сделанным, когда:

1. в `Agent_projects` лежат все 17 клонов;
2. в каждом есть `agents/` с полным набором папок;
3. в отчёте приведён вывод проверки — по строке на репозиторий: имя, текущая
   ветка, наличие `agents/`;
4. на диске за пределами `Agent_projects` ничего не изменилось.
